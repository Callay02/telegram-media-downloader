# Telegram 媒体批量下载器（Chrome 扩展）

一个 Manifest V3 的 Chrome 扩展：在 **Telegram Web（K 版 / A 版）** 里批量扫描、筛选、下载聊天中的
图片与视频。全部逻辑在本地浏览器完成，不联网、不上传任何数据。

---

## 1. 功能

| 能力 | 说明 |
| --- | --- |
| 批量扫描 | 一键扫描当前视图中已加载的所有图片 / 视频（含相册、GIF 视频、CSS 背景图形式的照片），**别人发来的消息同样收录** |
| 消息级按钮（主力） | 每条含图片的消息**气泡外侧**（没空间时退回气泡内右上角）会有一个下载按钮，**只下载这一条消息**里的图片，页面上其它消息一张都不碰；相册常显并带张数徽标；对方发的消息也有 |
| 只下当前消息 | 点击时用的是挂按钮那一刻快照下来的媒体 key 集合，所以即使页面上有一千张图，也只会入队这条消息里的那几张 |
| 选中即下载 | 你在 Telegram 里**多选消息**（右键消息 →「选择」）后，聊天区下方会浮出「下载选中的 N 张图片」，一键把选中消息里的图片全部入队；没选中的消息一张都不碰 |
| 视频也能下 | 选中下载默认只抓图片；只要选中的消息里有视频，按钮旁边会多出一个「🎬 N 个视频」小按钮，点它就把视频单独入队（流式视频走实时录制）。也可以一次开启「包含视频」，让主按钮图片+视频一起下 |
| 计数跨虚拟化 | Telegram 会回收滚出视口的消息 DOM，所以选中的图片是**边选边快照累积**的：选中 75 张后即使大半已滚出屏幕，按钮上依然显示 75，不会缩水、也不会重复计数 |
| 自动翻页 | 「自动加载全部」会反复把聊天滚动到顶部触发历史消息加载，直到连续三屏没有新内容 |
| 边滚边收 | 手动滚动聊天时自动识别新出现的媒体，随时补进列表 |
| 智能去重 | 按「聊天 + 消息 ID + 媒体序号」去重，重渲染 / 换 blob 地址不会重复收录 |
| 勾选下载 | 列表支持全选、反选、单个下载、只看已选、按类型（图片 / 视频）过滤 |
| 选中反馈 | 勾选的行会变蓝、左侧出现蓝条，并显示「**已选择**」字样；顶部有「已选择 N 项」徽标，底部按钮变成「下载选中 (N)」，一眼看清选了什么 |
| 命名模板 | `{chat} {date} {time} {index} {ext} {type} {mid}` 任意组合，可带子目录 |
| 并发队列 | 默认 2 并发，可在设置里调整；失败逐项标注原因并支持一键重试 |
| 进度反馈 | 实时进度条 + 每项状态；走 `chrome.downloads` 的文件还能拿到真实的完成 / 中断事件 |
| MSE 兜底 | 遇到 Telegram 用 MediaSource 推流的视频（直接读取会失败），可用 `MediaRecorder` 实时录制为 webm |
| 悬浮面板 | 页面右下角可拖拽面板，深色 / 浅色主题自适应；工具栏弹窗可远程遥控 |

## 2. 安装（加载已解压的扩展）

1. 打开 `chrome://extensions/`
2. 右上角打开 **开发者模式**
3. 点击 **加载已解压的扩展程序**，选择本目录（含 `manifest.json` 的那一层）
4. 打开 <https://web.telegram.org/>（K 版 `/k/` 或 A 版 `/a/` 都支持）
   *如果页面在安装扩展之前就已经打开，请刷新一次*，或直接点击工具栏图标 → 任意按钮，扩展会自动注入脚本。

## 3. 使用

1. 进入任意聊天（群 / 频道 / 私聊），把历史消息滚到你想下载的起点
2. 点右下角悬浮球打开面板
3. 选 **扫描当前视图**（只收当前已加载的）或 **自动加载全部**（自动向上翻页，耗时取决于网速）
4. 在列表里勾选要下载的项目（可先用类型 / 像素筛选、全选、反选）
5. 点 **下载选中**（或 **下载全部**）
6. 按需在「下载设置」里改文件名模板、子目录、并发数、录制兜底等

### 三个下载入口

| 入口 | 位置 | 作用范围 |
| --- | --- | --- |
| 消息级按钮 | 消息气泡旁边（外侧空白处；多图/相册常显并带张数，单图悬停显形） | **只下载这一条消息**里的图片，页面其它消息一张都不碰 |
| 选中下载按钮 | 在 Telegram 里多选消息后，聊天区下方居中浮现 | **只下载你选中的那些消息**里的图片，没选中的一律不碰 |
| 悬浮面板 | 右下角悬浮球 | 扫描 / 筛选 / 手动勾选 / 改命名模板，最完整的控制台 |

**视频怎么下**：和图片走同一套通道——能 `fetch` 到完整文件的（多为 mp4 blob）直接下载；Telegram 用 MediaSource 流式播放的，`fetch` 拿不到完整文件，改用 `MediaRecorder` **边播边录**成 webm，耗时约等于视频时长、画质有损，可在设置里关掉。录制必须能拿到那个 `<video>` 元素，所以**流式视频需要它还在屏幕上**；已滚出屏幕的选中视频，扩展会在提示里点名让你滚回去重试。

三个入口都**不区分发送者**，别人发来的图片同样能抓；想只要别人的，勾上面板里的「只看别人发的」过滤器。

> 这里**没有**「把整个对话/整页图片全下下来」的按钮 —— 扩展只会下载你明确指定范围的那些图片（某一条消息、或你选中的那几条消息）。

> 工具栏图标的弹窗提供同样的操作入口和实时统计。

## 4. 下载是怎么实现的（重要）

Telegram Web 的媒体不是普通 `<img src="https://...">`，而是页面自己用 `URL.createObjectURL`
生成的 `blob:` 地址；`blob:` 的读取权限绑定在「创建它的页面源」上。因此本扩展分三条通道：

```
content script（隔离世界）        页面主世界 inject.js
        │  postMessage 桥接              │
        │ ─────────────────────────────► │  fetch(blob:) 读回真实字节
        │ ◄───────────────────────────── │
        │                                │
   ┌────┴─────────────────────┐          │
   │ ≤ 1.25MB                 │          │
   │ 转成 data: URL           │          │
   │ → chrome.downloads       │          │  ✅ 支持子目录、能拿到完成/中断事件
   └──────────────────────────┘          │
   ┌──────────────────────────┐          │
   │ 更大 / 阈值更小          │          │
   │ 主世界 <a download> 直接点│          │  ✅ 任意体积，但只能落到默认下载目录
   └──────────────────────────┘          │
   ┌──────────────────────────┐          │
   │ fetch 失败（MSE 流）      │          │
   │ MediaRecorder 实时录制    │          │  ⚠️ 1x 速度、输出 webm
   └──────────────────────────┘          │
   ┌──────────────────────────┐          │
   │ src 本来就是 http(s) 直链 │          │
   │ fetch 被 CORS 拦 →        │          │
   │ 原样交给 chrome.downloads │          │  ✅ 不受 CORS 限制，走下载器并带 Cookie
   └──────────────────────────┘          │
```

* **小文件走 `chrome.downloads`**：可以带 `Telegram/{chat}/` 这样的子目录，也能区分「已完成 / 被中断」。
  这条通道要把内容塞进 `data:` URL，而 Chromium 对 URL 长度有约 **2MB 硬上限**（`url::kMaxURLChars`），
  所以二进制上限被硬压到 1.25MB —— 设置里填更大也没用。Telegram 的压缩图片大多在 100KB~1MB，能吃到目录；
  高清图和视频会走下面的 blob 通道（文件名被压平，落到默认下载目录）。
* **大文件走页面内 `<a download>`**：因为超大文件的 data URL 通道会吃掉大量内存；代价是子目录会被压平成
  `Telegram_群名_20240513_001.mp4` 这样的名字。
* **视频录制兜底（默认开启）**：K 版部分视频用 MediaSource 播放，`fetch` 拿不到完整文件，只能一边播放一边
  用 `MediaRecorder` 录成 webm。耗时 ≈ 视频时长，且会转码。不想要可以在设置里关掉。
* **CDN 直链通道**：少数版本（多为 A 版）的 `src` 是 `https://cdn.../file` 且不允许页面内 `fetch`，
  这时把原始地址交给浏览器的下载器，不受 CORS 约束，同样支持子目录。
* 连续触发多个下载时，Chrome 可能弹出「是否允许下载多个文件」，允许一次即可。

## 5. 文件名模板

默认：`{date}_{index}.{ext}`，子目录默认 `Telegram/{chat}`。

| 变量 | 含义 | 示例 |
| --- | --- | --- |
| `{chat}` | 当前聊天 / 频道名 | `设计群` |
| `{date}` | 消息时间（取不到就用当前时间） | `20240513` |
| `{time}` | 时分秒 | `143207` |
| `{index}` | 本次下载的递增序号 | `007` |
| `{ext}` | 依据真实 MIME 推断的扩展名 | `jpg` |
| `{type}` | `photo` / `video` | `photo` |
| `{mid}` | Telegram 消息 ID | `123456` |
| `{name}` | 预留（原文件名，若可得） | — |

示例：模板 `{chat}/{date}/{mid}_{index}.{ext}`、子目录 `TG` → `TG/设计群/20240513/123456_007.jpg`。
模板和子目录里的 `/` 会被当成目录层级（仅 `chrome.downloads` 通道生效）。

## 6. 设置项

| 设置 | 默认 | 说明 |
| --- | --- | --- |
| 文件名模板 | `{date}_{index}.{ext}` | 见上表 |
| 子目录 | `Telegram/{chat}` | 仅 downloads 通道生效 |
| 并发数 | `2` | 1–8；过大容易触发浏览器限流 |
| 走 downloads 的体积上限 | `1` MB | 受浏览器 URL 长度限制，实际最多 1.25MB；填 `0` = 全部走页面直接下载（无子目录） |
| 录制兜底最长时长 | `10` 分钟 | 超过则截断 |
| 滚动等待 | `1100` ms | 网络慢 / 消息多时调大更稳 |
| 视频录制兜底 | 开 | MSE 视频的 webm 实时录制 |
| 识别 CSS 背景图 | 开 | 部分版本照片用 `background-image` |
| 包含链接预览图 | 关 | 打开后网页预览 / 回复缩略图也会入列 |
| 含贴纸 | 关 | 打开后表情 / 贴纸也当媒体收 |
| 最小像素 | `64` px | 过滤头像等小图 |
| 滚动自动识别 | 开 | 弹窗里可切换 |
| 消息上的下载按钮 | 开 | 每条含图片（含视频，取决于下面的开关）的消息都会挂一个，位置自动选气泡外侧有空白的一边；**只作用于这条消息** |
| 选中下载悬浮按钮 | 开 | 检测到 Telegram 多选时显示「下载选中的 N 张图片」；数量为累积值（含已滚出屏幕的选中项），鼠标悬停可看到「来自几条消息 / 其中视频几个」 |
| 把视频也算作可下载内容 | 关 | 打开后：主按钮变成「下载选中的 N 张图片 + M 个视频」，消息级按钮也会把视频算进这条消息。不开也有个「🎬 N 个视频」小按钮可以单独下视频 |
| 只看别人发的 | 面板过滤器 | 列表里隐藏自己发出的媒体（识别不出方向时不会被误过滤） |

## 7. 已知限制

1. **只能下载已经加载进页面的媒体**：Telegram 是懒加载的，没滚到过的消息不在 DOM 里。
   「自动加载全部」会尽力翻页，但超大聊天仍可能需要多滚几轮。
2. **刷新页面后地址失效**：`blob:` 与页面生命周期绑定，刷新后请重新扫描。
3. **元素被回收**：滚太远时旧消息 DOM 可能被回收，此时点单条下载会提示「找不到 video 元素」——
   滚回该消息附近重新扫描即可。
4. **MSE 视频只能录**：录制是实时的、有损的（webm），并会跟随播放进度消耗视频时长。
5. **受保护内容 / 阅后即焚 / 语音等**不在支持范围（语音视频可下载，但本工具只勾选图片和视频）。
6. Telegram 若大改版 DOM 结构，选择器需要跟着更新（`src/content.js` 里的 `SEL` 常量集中维护）。

## 8. 排错

| 现象 | 处理 |
| --- | --- |
| 面板不出现 | 刷新 Telegram 页面；或点扩展图标 → 任意按钮触发自动注入 |
| 「主世界桥接超时」 | 刷新页面；确认扩展已启用且未被其他脚本拦截 `window.postMessage` |
| 每个文件都失败 | 先试单张图片；若「无法直接读取该媒体」，多为 MSE 视频，开启录制兜底 |
| 视频下载成 `.webm` 且体积偏小 | 走的是录制兜底（有损），画质受限于播放分辨率与时长 |
| 卡在「处理中」很久 | 并发调小；大批量任务建议先小范围试跑。走 downloads 通道的项目会自动回查真实状态，最长 30 分钟后给出结论 |
| 为什么大部分文件没有子目录 | 只有 ≤1.25MB 的文件走 `data:` 通道（受浏览器 URL 长度限制），其余走页面直下，无法带目录 |
| 下载文件散落在下载目录 | 大文件通道不支持子目录，可先在 Chrome 设置里开启「下载前询问保存位置」 |

## 9. 目录结构

```
telegram-media-downloader/
├── manifest.json          # MV3 清单：权限、content scripts（含 MAIN world）、popup、图标
├── src/
│   ├── background.js      # service worker：downloads API 落盘、下载状态回传、右键菜单
│   ├── inject.js          # 页面主世界：读取 blob、触发 <a download>、MSE 录制兜底
│   ├── content.js         # 扫描器 + 悬浮面板 + 命名模板 + 并发下载队列
│   ├── content.css        # 面板样式（含深色模式）
│   ├── popup.html/js/css  # 工具栏弹窗：快捷操作与统计
├── icons/                 # 16/32/48/128 图标
├── tools/
│   ├── make_icons.py      # 图标生成脚本（Pillow）
│   ├── selftest.js        # 离线自测：命名模板 / 路径清洗 / 下载路径合法性（30 项）
│   └── selftest-inject.js # 离线自测：主世界下载决策树（31 项）
└── README.md
```

### 开发者自测

两个自测脚本用 Node 内置 `vm` + 最小 DOM 桩加载真实源码，不需要浏览器：

```bash
node tools/selftest.js         # 30 项：模板变量、扩展名推断、路径穿越、下载路径清洗
node tools/selftest-inject.js  # 31 项：data/blob/remote/录制 四条分支 + URL 长度上限回归
```

清单本身可以用 Chrome 自带的打包命令校验（能打包成功即代表 manifest 合法）：

```bash
"/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" --pack-extension="$PWD/telegram-media-downloader"
```
